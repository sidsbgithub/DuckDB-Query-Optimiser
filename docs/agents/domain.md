# Domain docs

This repository uses a single-context layout:
- `CONTEXT.md` at the repository root holds domain vocabulary.
- `docs/adr/` holds architecture decision records.

Before exploring the codebase, read `CONTEXT.md` and ADRs
relevant to the area being explored.

If these files do not exist, proceed silently. The
domain-modeling skill creates them when terms or decisions
are resolved.

Use the glossary's terms when naming domain concepts in
issues, proposals, hypotheses, and tests. Note genuine
vocabulary gaps for domain-modeling.

If a proposal contradicts an ADR, explicitly identify the
ADR and explain why its decision should be reconsidered.
